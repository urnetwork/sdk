# Session controller handoff

The server, connect protocol, typed SDK APIs, device RPC and generated language bindings are ready for the separate session UI. This change does not add an app screen. See `server/session/REVOKE-UI-FINAL.md` for that work and `REVOKE-OPERATIONS.md` for server rollout and verified bounds.

Configure each owning `Api` before requests with `SetClientInfo(NewClientInfo(deviceType, appVersion))`. Supply the embedding app's version. Device types are `ios`, `android`, `macos`, `windows`, `linux`, `web`, `cli`, `server`, or `unknown`. Metadata follows API HTTP and H1/H3 authentication, including DeviceRemote RPC; it never supplies location or observation time.

API-only accounts use `api.OpenClientSessionViewController()`; device owners use `device.OpenClientSessionViewController()`. Go also has `NewClientSessionViewControllerWithApi(ctx, api)` and `WithDevice`. Call `Start`, subscribe with `AddClientSessionListener`, and read the immutable `GetSnapshot`. Use `SetVisible`/`SetForeground` for screen lifecycle, `Refresh` for manual refresh, and close subscriptions and controllers when done. Device owners should call `CloseClientSessionViewController` to release manager ownership. Bindings expose typed snapshot, action, error, session and last-use handles/getters; applications do not parse JSON to use native models.

Snapshots retain the last successful list during refresh errors and distinguish loading, refreshing, unsupported, and sign-in-required states. Session data includes current identity, creation/mint/token-expiry/acceptance times, kind, origin, nullable typed last use and revision `(generation,event_id)`. Last use includes Unix time, city, region, country, country code, device type and app version. Unknown location is empty and missing observation is null. Do not interpret mint time as activity, or last use as current connectivity. Healthy metadata lag may reach 120 seconds plus write and screen-refresh intervals.

Use `RevokeSession(id)` or `RevokeOtherSessions()`. Each action exposes its stable operation ID, status/state, loading, pending and typed error. A pending/202 or unknown/503 result is not success. The controller polls durable status with the same ID, even when hidden, and handles terminal cancelled/failed results explicitly. It captures the current credential generation at admission; an account switch cannot send an old action using the new account. Normal same-session background renewal can continue recovery.

The account APIs are `GetNetworkSessions`, `RevokeNetworkSession`, `RevokeOtherNetworkSessions` and `GetNetworkSessionOperation`; all select a network credential. Client tokens cannot perform account management. Bulk revoke requires a current tagged sign-in and never guesses a keep ID. A missing list route means unsupported; a target-session 404 does not hide the feature.

For API-only persistence, attach `SetNetworkCredentialStore(localState)`. Confirmed current-generation 401 rejection clears the persisted network login and emits one logout; a positively matching client session is cleared too. Unrelated client/device credentials are preserved and `AddAccountSignInRequiredListener` reports the account re-auth requirement. Failed storage is exposed by `GetCredentialPersistenceError` and the in-memory rejection fence prevents accidental re-adoption. 503, rate limits and transport errors do not sign the account out.

A logout's cause is `Api.GetAuthLogoutCause()`, or `GetAuthLogoutCause()` on the `Device` (DeviceLocal or DeviceRemote) whose `AuthLogout` fired. It is `AuthLogoutCauseSessionRevoked` (`"session_revoked"`) only when the server answered the rejected credential with its structured `session_revoked` 401, and `""` for every other logout, including a sign-out this app made (`SignOut`, or revoking the current session). Read it inside the listener; clearing the credential keeps it and a new login clears it. A DeviceRemote's API reads the server's status and body across the device RPC, so its cause is its own rejection's. A device whose session's network credential is rejected signs out through its own `AuthLogout`. The controller's `ClientSessionError.SessionRevoked` carries the same fact with `SignInRequired`. Show "This session was signed out from another device." only for this cause and generic sign-in-required wording otherwise. JavaScript reads `accountHost.getAuthLogoutCause()`, `device.getAuthLogoutCause()` and `error.session_revoked`; the C ABI has `urnet_api_get_auth_logout_cause`, `urnet_device_get_auth_logout_cause` and `urnet_client_session_error_get_session_revoked`.

Explicit account sign-out uses `Api.SignOut(callback)`. It attempts current-session revoke for at most two seconds and then clears the captured local login. `SessionSignOutResult` reports `RevocationConfirmed` separately from `CredentialCleared`; an offline sign-out must not claim server revocation. A newer login installed during the attempt is preserved. Keep the result/error visible if persistence fails.

JavaScript AccountHost and DeviceRemote expose `setClientInfo(deviceType, appVersion)` and `openClientSessionViewController()`. The JS controller exposes the corresponding camel-case methods and typed snapshots/listeners. `accountHost.signOut()` returns a `Promise<SessionSignOutResult>`. Native C/C++ exports and generated C#, Java, Python, Ruby and Rust bindings include typed session accessors and API-only controller creation; append-only symbol compatibility is verified.

Display `legacy_coverage: partial` honestly: original untagged network credentials are outside session-marker coverage. Updated tagged platform connections retire within 90 seconds and an honest leased P2P peer within the following 90 seconds under functioning timers and the clock bound. Existing unleased legacy P2P and colluding endpoints are outside this guarantee. Session removal is not equivalent to removing one client row.
